# 需求说明

## 1. 背景与目标

构建一个**完全本地运行**的语音转文字系统：用户在浏览器里上传音频，服务器在本机完成识别并返回文字。所有推理在本地 CPU 上完成，音频不离开用户机器，不依赖任何云端 ASR 服务。

目标用户是需要在离线或隐私敏感环境中做中英文转写的个人与小团队。

## 2. 功能需求

| 编号 | 需求 | 优先级 | 说明 |
|---|---|---|---|
| FR-1 | 上传音频文件并识别 | 必须 | 支持 wav / mp3 / m4a / flac / ogg / mp4 等常见格式与容器 |
| FR-2 | 中文识别 | 必须 | 普通话为主，兼容中英混说 |
| FR-3 | 英文识别 | 必须 | 带口音的英文也应可用 |
| FR-4 | 自动语种识别 | 必须 | 默认 `auto`，也允许用户显式指定 |
| FR-5 | 输出带标点文本 | 必须 | 中文逗号、句号、问号等 |
| FR-6 | 纯文本输出 | 必须 | `response_format=txt` |
| FR-7 | SRT 字幕输出 | 应该 | `response_format=srt`，时间戳来自 VAD 分段 |
| FR-8 | Web 界面 | 必须 | 拖拽上传、进度显示、结果复制/下载 |
| FR-9 | 服务健康检查 | 必须 | `GET /health`，模型加载期间也能响应 |
| FR-10 | 长音频处理 | 应该 | 通过 VAD 分段，避免整段进内存 |
| FR-11 | 模型完全离线 | 必须 | 首次下载后可断网运行 |
| FR-12 | 网页实时录音 | 必须 | 点击 Start Recording / Stop Recording 完成一次录音；展示状态与时长；单次最长 60 秒；权限拒绝或录音失败时提示原因；完成后可再次录音 |
| FR-13 | 音频回放 | 应该 | 上传文件和录音都能在页面内播放/暂停、拖动进度、显示当前时间与总时长；浏览器无法解码时提示但不影响识别 |
| FR-14 | 实时（流式）识别 | 必须 | 录音过程中持续采集麦克风音频，以分片方式发送到后端并不断返回增量文本，无需等待停止；停止后给出最终文本；允许使用 WebSocket 或 HTTP 分片；不要求模型原生支持流式推理，也不设毫秒级延迟指标 |

## 3. 非功能需求

| 类别 | 要求 |
|---|---|
| 运行环境 | Windows 11 x64，Python 3.12，普通 CPU（无独显亦可） |
| GPU | 可选。设置 `A2T_DEVICE=cuda` 即可启用，无需改代码 |
| 依赖管理 | pip + requirements.txt；不引入 npm / 容器等额外工具链 |
| 性能 | 4 核 CPU 上，1 小时音频应在 5–15 分钟内完成 |
| 内存 | 常驻不超过 2GB（SenseVoice + VAD） |
| 并发 | CPU 上推理串行；并发请求排队而不是并行抢占 |
| 上传限制 | 单文件默认 ≤ 10MB（`A2T_MAX_UPLOAD_MB` 可调）；后端分块累计，超限立即返回 413 |
| 实时识别延迟 | 常见停顿下，已说完的句子在 1–2 秒内出现在页面上；不做毫秒级要求 |
| 实时识别资源 | 未提交缓冲上限 6 秒，解码成本不随录音变长而平方增长；单次最长 60 秒 |
| 可测试性 | 默认测试不加载模型、不依赖麦克风，10 秒内跑完 |
| 可复现性 | 提供 requirements.lock.txt 锁定精确版本 |

## 4. 范围之外（本期不做）

- 模型原生的流式推理（当前用分片 + 滚动重解码实现近实时，不改造模型）
- 说话人分离（diarization）
- 热词 / 领域词表定制
- 多用户、鉴权、配额
- 任务持久化与断点续跑（当前为同步请求模型）
- 移动端适配优化

## 5. 必要假设

1. 用户能访问 ModelScope 下载模型；此后可离线。
2. 输入音频包含可识别的人类语音，采样率与编码由 ffmpeg 统一处理。
3. 单文件不超过 10MB（默认上限，可用 `A2T_MAX_UPLOAD_MB` 调整）；可处理时长取决于编码与码率。
4. 服务默认只监听 `127.0.0.1`，不对外暴露。
5. 用户接受首次请求需等待模型加载（约 10–20 秒），或等待预热完成。
6. 用户使用支持 `MediaRecorder` 的最新版 Chrome / Edge，并愿意授予麦克风权限。
7. 录音页面运行在安全上下文（`localhost` / `127.0.0.1` 或 HTTPS）。
8. 实时识别假定浏览器支持 `AudioWorklet` 与 `WebSocket`；不满足时退回「先录后上传」，功能仍可用。

## 6. 边界条件

| 场景 | 行为 |
|---|---|
| 空文件 | `400`，提示文件为空 |
| 超过 10MB | `413`；有 `Content-Length` 时在 multipart 解析前拒绝，未声明时在分块写入阶段中断，不进入解码 |
| 不支持的扩展名 | `415`，不进入解码流程 |
| 文件实际损坏 | `400`，返回 ffmpeg 的错误摘要 |
| 模型仍在加载 | `/health` 返回 `warming`；转写请求会等待锁释放 |
| 推理异常 | `500`，返回异常信息，不泄漏堆栈到前端 |
| 并发请求 | 排队处理，第二个请求的耗时包含等待时间 |
| 无语音音频 | 返回空字符串，不报错；前端提示「没有识别到语音内容」 |
| 麦克风权限被拒绝 | 提示「麦克风权限被拒绝」及处理建议，不开始录音 |
| 没有麦克风 / 设备被占用 | 提示具体原因，可重试 |
| 录音短于 300ms | 提示录音过短，不提交识别 |
| 录音达到 60 秒 | 自动停止并提交该次录音 |
| 录音过程中重复点击 | 开始/停止按钮按状态禁用，避免并发录音 |
| 录音中关闭/刷新页面 | `beforeunload` 提示；未提交的录音丢弃 |
| 录音无语音或全是噪声 | 识别结果为空，提示未识别到内容，可再次录音 |
| 浏览器不支持音频编码 | 播放按钮禁用并提示「无法预览，但仍可正常识别」，识别流程不受影响 |
| 录音的 WebM 缺少时长元数据 | 使用录音计时作为总时长，进度条仍可正常拖动 |
| 实时识别连接失败 / 浏览器不支持 AudioWorklet | 录音继续，页面提示「实时识别不可用」，停止后自动上传识别 |
| 实时识别时模型仍在加载 | WebSocket 返回 `error` 并关闭，前端提示模型未就绪 |
| 实时识别超过 60 秒 | 服务端按上限截断并返回 `final`，前端同时自动停止录音 |
| 实时识别音频帧过大（> 512KB） | 返回 `error`，不写入缓冲 |
| 实时识别过程中客户端断开 | 服务端清理临时缓冲与临时文件，不影响其他会话 |
| 说话没有停顿 | 未提交缓冲到 6 秒时强制提交，文本不会卡住不更新 |

## 7. 验收标准

1. `pytest` 全绿（默认跳过慢速用例）。
2. `pytest -m slow` 在真实模型下通过：中文、英文样例的字符相似度 ≥ 0.6。
3. 浏览器上传 `samples/chinese.wav`，5 秒内返回带标点的中文文本。
4. `curl -F file=@samples/english.wav http://127.0.0.1:8000/api/transcribe` 返回英文文本。
5. 断网（`A2T_OFFLINE=1`）且模型已下载时，服务仍可正常转写。
6. 点击 Start Recording 授权后可开始录音，页面显示录音状态与时长；点击 Stop Recording 后自动提交并显示识别结果。
7. 拒绝麦克风权限、无设备或设备被占用时，页面显示对应的失败原因。
8. 持续录音到 60 秒时自动停止并提交，不会无限录制。
9. 一次识别完成后 Start Recording 恢复可用，可连续录制多段。
10. 上传文件和录音都能点击播放/暂停，进度条与 `当前时间 / 总时长` 正确更新；录音总时长与录音计时一致。
11. 上传超过 10MB 的文件返回 `413`，服务端在读取过程中即中断；前端在选择文件时提前提示上限。
12. Windows 11 下执行 `python -m pip install -r requirements.txt` 与 `python -m uvicorn app.main:app --host 127.0.0.1 --port 8000` 即可完成安装并启动，无需单独安装 PyTorch 或激活虚拟环境。
13. 点击 Start Recording 后持续说话，页面在停止前就不断出现识别文本；点击 Stop Recording 后得到最终文本。
14. 实时识别中断（WebSocket 失败）时录音不丢，停止后仍能通过上传接口得到识别结果。
